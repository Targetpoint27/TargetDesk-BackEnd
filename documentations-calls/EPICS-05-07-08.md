## EPIC-05: Intégration CRM

### Lier un Client à un Appel

**POST** `/call-center/calls/{id}/link-client`

Associe un appel existant à une fiche client du CRM pour un suivi centralisé.

**Exemple de requête:**
```bash
curl -X POST http://targetdesk-backend.test/api/v1/call-center/calls/15/link-client \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": 5
  }'
```

**Paramètres d'URL:**
- `id` (integer, requis) - ID de l'appel

**Champs requis:**
- `client_id` (integer, requis) - ID du client dans le CRM

### Réponse de succès (200 OK)
```json
{
  "success": true,
  "message": "Appel associé au client avec succès",
  "data": {
    "id": 15,
    "call_id": "CALL-2026-0015",
    "type": "entrant",
    "phone_number": "0612345678",
    "caller_name": "Jean Dupont",
    "client_id": 5,
    "status": "en_cours",
    "created_at": "2026-02-08T10:00:00.000000Z",
    "updated_at": "2026-02-08T15:30:00.000000Z",
    "client": {
      "id": 5,
      "name": "ACME Corporation",
      "code": "ACME-001",
      "email": "contact@acme.com",
      "phone": "0612345678"
    }
  }
}
```

### Fonctionnalités automatiques

✅ **Lien client** - Association créée dans la base  
✅ **Relation chargée** - Informations client incluses dans la réponse  
✅ **Audit logging** - Association loggée avec détails

### Cas d'usage

- Identifier un appelant comme client existant pendant l'appel
- Créer un historique d'appels pour un client
- Centraliser toutes les interactions client
- Faciliter le suivi commercial

### Erreurs possibles

**404 - Not Found:**
```json
{
  "success": false,
  "message": "Appel non trouvé"
}
```

**422 - Validation Error:**
```json
{
  "success": false,
  "message": "Validation errors",
  "errors": {
    "client_id": ["L'ID du client est obligatoire"]
  }
}
```

**500 - Server Error:**
```json
{
  "success": false,
  "message": "Erreur serveur"
}
```

## EPIC-07: Reporting

### Consulter l'Activité Quotidienne

**GET** `/call-center/reports/daily`

Affiche l'activité quotidienne de l'agent: liste des appels traités, KPIs et graphiques de performance.

**Exemple de requête:**
```bash
curl -X GET "http://targetdesk-backend.test/api/v1/call-center/reports/daily?date=2026-02-07" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json"
```

### Paramètres de requête (optionnels)

- `date` (string, optionnel) - Date spécifique au format YYYY-MM-DD (défaut: aujourd'hui)

### Réponse de succès (200 OK)
```json
{
  "success": true,
  "message": "Activité quotidienne récupérée",
  "data": {
    "date": "2026-02-07",
    "summary": {
      "total_treated": 15,
      "total_closed": 10,
      "total_in_progress": 5,
      "total_time_seconds": 14400,
      "avg_time_per_call": "00:16:00"
    },
    "graphs": {
      "by_status": {
        "cloture": 10,
        "en_cours": 3,
        "en_attente": 2
      },
      "by_type": {
        "entrant": 12,
        "sortant": 3
      }
    },
    "calls": [
      {
        "id": 1,
        "time": "14:30",
        "type": "entrant",
        "caller": "ACME Corporation",
        "object": "Problème technique",
        "status": "cloture",
        "duration": 600
      },
      {
        "id": 5,
        "time": "13:15",
        "type": "sortant",
        "caller": "Marie Dubois",
        "object": "Rappel satisfaction",
        "status": "cloture",
        "duration": 300
      },
      {
        "id": 8,
        "time": "11:45",
        "type": "entrant",
        "caller": "0612345678",
        "object": "Demande devis",
        "status": "en_cours",
        "duration": 0
      }
    ]
  }
}
```

### Structure de la réponse

**Résumé (summary):**
- `total_treated` (integer) - Nombre total d'appels traités ce jour
- `total_closed` (integer) - Nombre d'appels clôturés
- `total_in_progress` (integer) - Nombre d'appels encore en cours
- `total_time_seconds` (integer) - Temps total passé en secondes
- `avg_time_per_call` (string) - Temps moyen par appel (format HH:MM:SS)

**Graphiques (graphs):**
- `by_status` - Répartition par statut
- `by_type` - Répartition par type (entrant/sortant)

**Liste d'appels (calls):**
- `time` - Heure de dernière activité
- `caller` - Nom du client ou numéro de téléphone
- `duration` - Durée en secondes

### Logique de calcul

**Filtrage:** Appels assignés à l'agent avec `updated_at` correspondant à la date  
**Temps total:** Somme de `treatment_time_seconds` + `call_duration_seconds`  
**Temps moyen:** Total ÷ Nombre d'appels traités

### Cas d'usage

- Bilan de fin de journée pour l'agent
- Suivi de productivité quotidienne
- Analyse des types d'appels traités
- Export pour reporting hiérarchique

### Erreurs possibles

**401 - Unauthenticated:**
```json
{
  "message": "Unauthenticated."
}
```

**500 - Server Error:**
```json
{
  "success": false,
  "message": "Erreur lors de la récupération du rapport"
}
```

```json
      "last_activity": "2026-02-08T12:00:00.000000Z"
    }
  ]
}
```

### Structure de la réponse

**Métriques par agent:**
- `id` - ID de l'agent
- `name` - Nom de l'agent
- `status` - Statut (active/inactive/unknown)
- `calls_today` - Nombre d'appels traités aujourd'hui
- `active_calls` - Nombre d'appels en cours actuellement
- `avg_handling_time` - Temps de traitement moyen (format HH:MM:SS)
- `load_status` - Indicateur de charge:
  - `"vert"` - Charge normale (< 1 appel actif)
  - `"orange"` - Charge moyenne (1-2 appels actifs)
  - `"rouge"` - Surcharge (≥ 3 appels actifs)
- `last_activity` - Dernière activité de l'agent

### Calcul du load_status
```
active_calls >= 3  → "rouge"
active_calls >= 1  → "orange"
active_calls < 1   → "vert"
```

### Cas d'usage

- Monitoring temps réel de l'équipe
- Identification des agents surchargés
- Répartition équitable de la charge
- Décision de réassignation d'appels

### Erreurs possibles

**500 - Server Error:**
```json
{
  "success": false,
  "message": "Erreur récupération vue équipe"
}
```

### Statistiques d'Équipe

**GET** `/call-center/supervisor/team-stats`

Récupère les KPIs globaux de l'équipe: volume d'appels, taux de réponse, SLA, satisfaction.

**Exemple de requête:**
```bash
curl -X GET "http://targetdesk-backend.test/api/v1/call-center/supervisor/team-stats?period=week" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json"
```

### Paramètres de requête (optionnels)

- `period` (enum, optionnel) - Période d'analyse:
  - `"today"` - Aujourd'hui
  - `"week"` - Cette semaine

```json
  "data": {
```

**KPIs:**
- `total_calls` - Volume total d'appels
- `missed_calls` - Nombre d'appels manqués

- `avg_wait_time` - Temps d'attente moyen
- `sla_compliance` - Respect des SLA (%)

**Graphiques:**
- `volume_evolution` - Évolution du volume par date
- `status_distribution` - Répartition par statut

### Cas d'usage

- Rapport de performance hebdomadaire/mensuel
- Analyse des tendances d'activité
- Identification des pics d'appels
- Planification des ressources

### Réassigner un Appel

**PUT** `/call-center/supervisor/calls/{id}/reassign`

Transfère un appel d'un agent à un autre pour équilibrer la charge de travail.

**Exemple de requête:**
```bash
curl -X PUT http://targetdesk-backend.test/api/v1/call-center/supervisor/calls/15/reassign \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "new_agent_id": 2,
    "reason": "Agent initial surchargé avec 5 appels en cours"
  }'
```

**Paramètres d'URL:**
- `id` (integer, requis) - ID de l'appel à réassigner

**Champs requis:**
- `new_agent_id` (integer, requis) - ID du nouvel agent

**Champs optionnels:**
- `reason` (string, optionnel) - Motif de la réassignation

### Réponse de succès (200 OK)
```json
{
  "success": true,
  "message": "Appel réassigné avec succès",
  "data": {
    "id": 15,
    "call_id": "CALL-2026-0015",
    "type": "entrant",
    "phone_number": "0612345678",
    "caller_name": "Jean Dupont",
    "status": "en_cours",
    "assigned_to": 2,
    "created_at": "2026-02-08T10:00:00.000000Z",
    "updated_at": "2026-02-08T16:00:00.000000Z",
    "assigned_agent": {
      "id": 2,
      "name": "Pierre Martin",
      "email": "pierre@targetpoint.fr"
    }
  }
}
```

### Fonctionnalités automatiques

✅ **Assignation mise à jour** - `assigned_to` changé  
✅ **Historique enregistré** - Trace dans `call_status_history` avec:
  - Ancien et nouveau agent
  - Motif de réassignation
  - Identité du superviseur
✅ **Audit logging** - Action loggée avec détails complets

### Cas d'usage

- Équilibrer la charge entre agents
- Transférer un appel à un expert spécifique
- Gérer les absences/pauses agents
- Optimiser le temps de traitement

### Erreurs possibles

**404 - Not Found:**
```json
{
  "success": false,
  "message": "Appel non trouvé"
}
```

**500 - Server Error:**
```json
{
  "success": false,
  "message": "Erreur lors de la réassignation"
}
```
